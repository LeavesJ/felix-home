# Roadmap, 2026-09-23 to 2027-01-31

On 2026-09-22 the founder made Felix a commercial product for other people's
projects, built first and best on Claude Code (#290). This is the build order
that follows. It replaces the queue order of
[direction-decisions](2026-09-19-direction-decisions.md) §5 and nothing else:
v3.2, the conformance amendments and the constitution's invariants govern
unchanged.

How it was made: a harvest of 58 open items from the repository's own records,
the v3.2 build order and the founder's calendar; two drafts from opposite
angles (users first, mechanism first); two critics against both (market clock,
doctrine and feasibility). This is the synthesis. Sizes are in sessions, where
one session is one medium engine PR.

## 1. What the decision changes

- **The yardstick.** A change is judged by whether it survives a stranger
  adopting it, not only by whether it works on the five repositories here.
  That turns several settled things into blockers:
    - the install footprint: prompt starts are logged, commissioning installs
      seven plugins at user scope, candidates are cloned weekly;
    - the Stop hold addresses every adopter as "the founder" and offers
      `exceptions.tsv` where no grant can reach it (`hooks/stop:467-471`);
    - deny rows read heredoc bodies and quoted prose as commands;
    - a governed project's tables and ledger live in the private felix-home,
      which a stranger does not have and which can never be public;
    - once tables move into the governed repository, a pull request could edit
      its own rules unless the check reads them from the base ref;
    - whether `felix gate` runs on a CI runner with no `claude` CLI is unproven
      (`lib/ready.sh`, `lib/resolve.sh` call it).
- **The order.** The merge-point check and the qualified judge move up.
  `felix dispatch` moves from fifth to February at the earliest, after a
  ride-along adapter, because the integration order is now merge-point check,
  then adapters, then dispatch on the customer's own key.
- **The measure.** Value is claimed only against ground truth outside Felix:
  a sealed seeded-omission corpus against a control arm, whether outside users
  keep the block on after its first false block, the false-block rate with its
  source named, and the bypass rate.
- **The founder's part.** Fewer design questions, more outreach, and a short
  list of acts batched into the windows in §6.

## 2. Where this starts

- **The obligations request ran on Elenchus (queue item 4a), 2026-09-22.**
  Answered blind: a subagent that loads no memory and was told nothing about
  what to look for, on a clean clone at origin/main `a45a985` with the web
  extra installed so the route probe could see (16 routes). Counts: 7
  proposed, 7 accepted by the reader, 0 refused, 0 admitted. Six of the seven
  evidence commands fail on main today.
    - This is calibration, not recall. `public_bind_has_spend_ceiling` (a
      public bind through `python -m elenchus.web` with no ceiling) is
      LeavesJ/Elenchus#16, open since 2026-09-03, and `app.py:74` says
      "Unset means unbounded". The design doc had also named the expected
      row. Rediscovering a known hole blind shows the protocol works; it does
      not show it finds unknown ones.
    - The other five are not yet checked against what Elenchus already knows:
      the invitee launcher binds 0.0.0.0 by default; `/api/health` reports ok
      with no model key; FastAPI's `/docs`, `/redoc` and `/openapi.json` are
      served; no request text field is length-bounded; CI runs 3.14 against a
      declared 3.12 floor.
- **In flight in other sessions, landed by their owners:** the table
  validator (`claude/table-validator`), qualification hardening (touches
  `lib/qualify.sh`, so it lands before the judge work), PR #291 (red).
- **Capacity.** About 4-5 backlog units a week sustained; fixes are 57% of
  engine PRs, and the weekly usage limit binds (hit 2026-09-22). Research and
  critique workflows spend the same budget as engine work.

## 3. The plan

Four tracks: **A** demand (the founder), **B** the stranger's path, **C** the
qualified judge, **D** the public proof.

### Phase 0 — Sep 23 to Oct 4: land what is in flight, probe demand

- **A.** The founder sends 10-15 heavy Claude Code users the public one-liner:
  clone LeavesJ/Felix and run `felix audit`. It is read-only, needs no model
  and no `claude` CLI, and raises no vendor-terms question. Record how many
  ran it, their share of stops on unchecked edits, and how many asked to try
  the block. `felix audit` reads transcripts on the user's machine; it cannot
  screen a public repository.
- **B.** Qualification hardening, then the table validator (commission
  re-stamp after). PR #291 fixed or closed. The workflow filter in
  `automerge.sh` and `repair.sh` (0.5) — overdue, since Elenchus already runs
  three workflows. Epoch portability under two PATHs (1). The `granted`
  assertion stops skipping (0.5).
- **B.** Deny rows stop matching prose and heredocs (1, adversarial tier),
  then the Elenchus and Veldra marker deny rows (amendments §0 residual), in
  that order: the marker row is the one that refused prose.
- **B.** A 0.5-session probe: `felix gate` on a GitHub runner with no `claude`
  CLI. If it fails, the merge-point check needs a redesign, found before
  recruiting.

### Phase 1 — Oct 5 to Nov 1: the smallest product a stranger can adopt

Oct 12-18 asks nothing of the founder; engine work continues.

- **C.** In forced order: obligations gain `capabilities_needed` (1-1.5), then
  control 7, the per-member coverage report (1), then the qualified-judge join
  (2-3): an obligation is discharged only by a checker that has met all seven
  controls, otherwise it reads UNKNOWN and names the capability it needs,
  including the independence checker's two decoupled controls. Then the judge
  is pinned to main's engine (1-2). **No row is armed before control 7 and the
  pin exist** (amendments §2.1, §2.3). Demonstration on Elenchus: the
  qualified checker FAILs at `a45a985` and PASSes at #16's head.
- **B.** Footprint (2): no prompt logging by default, no user-scope installs,
  no weekly clone; a before/after listing of a clean HOME shows only Felix's
  directory changed. Onboarding wording (1): the Stop hold stops saying "the
  founder"; the README's Direction section follows the new integration order.
- **B.** A hooks-mode solo pilot from a pinned public sha, tables in the
  user's own clone of Felix (README: a clone that ships `projects/` is its own
  home). Private repositories included.
- **B.** The ledger's move into the governed repository, designed with
  refuters: tables and ledger in the repository, evaluated from the base ref
  and the stricter of base and head taken, so a pull request cannot weaken its
  own obligation or qualification row.
- **D.** A sealed seeded-omission corpus written by an agent blind to the
  engine, run against a control arm of plain Claude Code before any user
  arrives (1). Without it, recall has no denominator.
- **Exit.** A session with no felix-home access installs Felix from the README
  on a fresh HOME. The footprint diff holds. The Elenchus judge demonstration
  holds and was shown failing first. The control-arm baseline is recorded.

### Phase 2 — Nov 2 to Dec 6: cohort 1 on their own repositories

- **A.** The snapshot is published Nov 2-4. 3-5 audit respondents install,
  growing to 5-10. Pre-registered thresholds, a frozen pilot sha with fixes
  labelled before and after, a 40% defect reserve, and every recall miss given
  a cause: not admitted, admitted but unqualified, or missed by the checker.
- **B.** The ledger relocation is built (2-3), then the merge-point required
  check (3-4): Felix at a public sha, `enforce_admins` left false and admin
  merges counted as bypass, offered to cohort 1 when it holds. A forgery run
  (1) that includes a pull request editing its own tables.
- **D.** Per-claim receipts that name their judge and go stale when an input
  outside the tree changes while the tree hash does not (2), and
  `coverage.tsv` with its offline citation check (2), both before the wedge.
  The wedge (2-3) is built in a private staging repository: one obligation's
  whole life, UNKNOWN to blocking to discharged by a qualified judge to stale
  to dormant through grounded topology, replayed byte-identically on a clean
  runner against a transcript written blind beforehand, with a privacy canary.

### Phase 3 — Dec 7 to Dec 18: finals, engine only

Receipts record author and verifier (1); the enforcing path reads the git
author of an admitting commit (1); another plugin's JSON deny is accounted
(0.5); the defects cohort 1 found. Nothing is asked of the founder.

### Phase 4 — Dec 19 to Jan 31: readout and proof

- **A.** Readout by Jan 3 against the pre-registered thresholds: continue,
  narrow or pivot.
- **D.** The wedge is published to a separate public repository once the
  canary and footprint criteria hold. felix-home stays private.
- **B.** The harvest rows (2-3), after which the founder sets ECC's
  `hooks_enabled` false.
- **If continue.** The Codex ride-along adapter (3-5; `apply_patch` must meet
  the deny rows and the Stop hold) and cohort 2 on the merge-point check.
  `felix dispatch` v0 in February at the earliest.

## 4. Not before February

`felix dispatch` and leases; the discovery schedule; discovery budgets, the
dispute protocol and the stopping rule; the Docker sandbox and behaviour
receipts; DSSE or in-toto receipts (and never a key on the enforcing path);
retiring the router (a charter change); team concurrency; a Factory Droid
adapter; pricing.

## 5. Signals that change the plan

- Fewer than 3 of the Phase 0 audit recipients run it, or none asks for the
  block: re-target the user profile before spending Phase 1.
- Fewer than 5 installs by Dec 4 from at least 15 screened: stop mechanism
  work and fix the path to adoption.
- Under 60% of users who met a false block still have the block on 14 days
  later: move cohort 2 to report-only.
- Felix's seeded-omission recall does not beat the control arm: discovery
  adds nothing over a plain session; narrow the product to the merge-point
  check for obligations people name.
- The false-block rate stays above 20%: stop feature work and fix its sources.
- More than 25% of pilot merges pass a red or missing check: the block is
  decorative; decide enforcement with the founder or accept an advisory
  position.
- Factory ships next-generation Missions with standing obligations, or
  Anthropic ships standing, blocking project obligations: re-verify the
  market before the next phase.

## 7. Corrections recorded here

- The 2026-09-22 plan said existing qualification rows stay report-only and
  new rows are armed. Amendments §2.1 forbids arming before all seven controls
  hold, and control 7 does not exist; §2.3 requires the judge pinned outside
  the tree it judges. Nothing arms until both land.
- The Elenchus run is calibration, not an independent corroboration: the hole
  it found was already an open pull request and a code comment.
- `felix audit` screens people, from their transcripts; it cannot screen a
  repository.
- `enforce_admins` stays false on a stranger's repository: true locks a solo
  maintainer out of their own main branch, and branch protection there is
  theirs to set.

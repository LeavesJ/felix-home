# Roadmap, 2026-09-23 to 2027-01-31

On 2026-09-22 the founder made Felix a product for other people's projects,
built first and best on Claude Code (#290). On 2026-09-23 he set the order:
**build Felix first.** Obligations have to be real and the machinery has to
work before anything else; commercialisation is a natural outcome of Felix's
quality, not a goal to plan toward. This is the build order that follows. It
replaces the queue order of
[direction-decisions](2026-09-19-direction-decisions.md) §5 and nothing else:
v3.2, the conformance amendments and the constitution's invariants govern
unchanged.

How it was made: a harvest of 58 open items from the repository's own records,
the v3.2 build order and the founder's calendar; two drafts from opposite
angles; two critics against both. The first version of this file (#293) led
with an outside-user track; the founder withdrew it the next day, and this
version keeps the mechanism-first draft's order with the critics' corrections.
Sizes are in sessions, where one session is one medium engine PR.

## 1. What changes

- **Build first.** No outreach, no user deadlines, no plan driven by demand.
  `felix audit` stays public as it is; outside use follows when the whole-life
  replay holds and the merge-point check stands.
- **The yardstick is quality.** "Survives a stranger adopting it" (#290) is a
  design criterion, not a sales one: the install footprint, a Stop hold that
  addresses every adopter as "the founder", deny rows that read prose as
  commands, tables living in the private felix-home, and a pull request able to
  edit its own rules once tables move into the repository are defects in Felix,
  and are scheduled as such.
- **Every mechanism is shown on more than Elenchus.** A demonstration counts
  when it holds on Elenchus and on at least one project in another ecosystem
  (Veldra, sv2-apps, or the bash harness itself): build the class, not the
  instance.
- **The order.** Obligations and the qualified judge first, then evidence that
  goes stale, then the whole-life replay, then the merge-point check.
  `felix dispatch` waits until February at the earliest, after a ride-along
  adapter, because the integration order is merge-point check, then adapters,
  then dispatch on the customer's own key.
- **Value is claimed only against ground truth outside Felix**: a sealed
  seeded-omission corpus against a control arm, replay on a clean machine,
  false blocks in real sessions.

## 2. Where this starts

- **The obligations request ran on Elenchus (queue item 4a), 2026-09-22.**
  Answered blind: a subagent that loads no memory and was told nothing about
  what to look for, on a clean clone at origin/main `a45a985` with the web
  extra installed so the route probe could see (16 routes). Counts: 7
  proposed, 7 accepted by the reader, 0 refused, 0 admitted. Six of the seven
  evidence commands fail on main today.
    - This is calibration, not recall. `public_bind_has_spend_ceiling` (a
      public bind through `python -m elenchus.web` with no ceiling) is
      LeavesJ/Elenchus#16, open since 2026-09-03, and `app.py:74` says
      "Unset means unbounded". The design doc had also named the expected
      row. Rediscovering a known hole blind shows the protocol works; it does
      not show it finds unknown ones.
    - The other five are not yet checked against what Elenchus already knows:
      the invitee launcher binds 0.0.0.0 by default; `/api/health` reports ok
      with no model key; FastAPI's `/docs`, `/redoc` and `/openapi.json` are
      served; no request text field is length-bounded; CI runs 3.14 against a
      declared 3.12 floor.
    - The request pointed at a scratch clone that will not outlive the
      session. The answer and `candidates.tsv` are in the Elenchus memory
      root; any re-run uses a durable clone.
- **In flight in other sessions, landed by their owners:** the table
  validator (`claude/table-validator`), qualification hardening (touches
  `lib/qualify.sh`, so it lands before the judge work), PR #291 (red).
- **Capacity.** About 4-5 backlog units a week sustained; fixes are 57% of
  engine PRs, and the weekly usage limit binds (hit 2026-09-22). Research and
  critique workflows spend the same budget as engine work.

## 3. The plan

### Phase 0 — Sep 23 to Oct 4: land what is in flight, make obligations real

- Qualification hardening, then the table validator (commission re-stamp
  after). PR #291 fixed or closed.
- The founder admits or refuses each of the seven Elenchus candidates, with
  the class he can defend. Felix first checks the five unverified ones against
  what Elenchus already records, so he decides on facts.
- The workflow filter in `automerge.sh` and `repair.sh` (0.5), overdue since
  Elenchus already runs three workflows. Epoch portability under two PATHs
  (1). The `granted` assertion stops skipping (0.5).
- Deny rows stop matching prose and heredocs (1, adversarial tier), then the
  Elenchus and Veldra marker deny rows (amendments §0 residual), in that order:
  the marker row is the one that refused prose.
- The obligations request on a second project in another ecosystem, answered
  blind the same way, so derivation is not an Elenchus result (1).
- A 0.5-session probe: `felix gate` on a GitHub runner with no `claude` CLI,
  so the merge-point check's design is known early.
- Restart moments, step 1a (1.5-2, adversarial tier;
  [scope](2026-09-23-restart-moments-scope.md) §2), in the last days of the
  phase, once #307 is on main (it is). Felix detects a session whose hooks
  run an older engine than the one installed, and `felix gate`, `handoff` and
  `merge` run from such a copy name the installed CLI. It records the moment
  in shadow and puts nothing on the founder's screen. It comes this early
  because most Stops this week ran a superseded engine, so every Phase 0-1
  engine fix reaches running sessions late. A gate or merge on an old CLI is
  one of the three known misses.

### Phase 1 — Oct 5 to Nov 1: the qualified judge

- In forced order: obligations gain `capabilities_needed` (1-1.5); control 7,
  the per-member coverage report (1); the qualified-judge join (2-3): an
  obligation is discharged only by a checker that has met all seven controls,
  otherwise it reads UNKNOWN and names the capability it needs, including the
  independence checker's two decoupled controls; then the judge pinned to
  main's engine (1-2). **No row is armed before control 7 and the pin exist**
  (amendments §2.1, §2.3).
- Demonstration on Elenchus: the qualified checker FAILs at `a45a985` and
  PASSes at #16's head, shown failing first. And on the second project.
- A sealed seeded-omission corpus written by an agent blind to the engine,
  run against a control arm of plain Claude Code (1). This measures whether
  discovery adds anything over a plain session.
- `coverage.tsv` with its offline citation check (2), the rest of queue item
  2, born on the validator.
- Restart moments, step 1b (1.75-2.25; scope §4), outside the judge chain's
  forced order and after #310. It touches none of the judge files (qualify,
  obligations, receipts). It lands after at least 7 days and 10 rows of 1a in
  shadow, and says one line per session to the person (allowed 2026-09-23).
  The speech switches on only after the founder's look at the probe line
  (scope §3); until then 1b lands with speech off. The acceptance read (0.25)
  comes at 20 said rows or 3 weeks, before Phase 2 fixes its content.
  Step 2, a real restart past 500K, is not scheduled here: it waits on the
  handoff repair (§6) and on this read.

### Phase 2 — Nov 2 to Dec 6: evidence that goes stale, and the ledger in the repository

- Per-claim receipts that name their judge, with an id and evidence refs, and
  that go stale when an input outside the tree changes while the tree hash
  does not (2), each assertion shown failing first.
- Receipts record author and verifier (1); the enforcing path reads the git
  author of the commit that admitted an obligation (1).
- The ledger's move into the governed repository, designed with refuters and
  then built (3-4): tables and ledger in the repository, evaluated from the
  base ref with the stricter of base and head taken, so a pull request cannot
  weaken its own obligation or qualification row.
- The whole-life replay (2-3), built in a private staging repository: one
  obligation from UNKNOWN to blocking, discharged by a qualified judge, stale
  when an outside input moves, dormant only through grounded topology,
  replayed byte-identically on a clean runner with an empty HOME, no `claude`
  CLI and no network, against a transcript written blind beforehand, with a
  privacy canary.

### Phase 3 — Dec 7 to Dec 18: finals, engine only

Defects; another plugin's JSON deny accounted (0.5); the footprint (2): no
prompt logging by default, no user-scope installs, no weekly clone, checked by
a before/after listing of a clean HOME; the Stop hold's wording stops saying
"the founder" (1); `tests/run` and `felix` split or indexed (1-2). Nothing is
asked of the founder.

### Phase 4 — Dec 19 to Jan 31: the replay goes public, the check stands

- The whole-life replay is published to a separate public repository once the
  canary and footprint criteria hold. felix-home stays private.
- The merge-point required check (3-4): Felix at a public sha, run from the
  base-ref tables, `enforce_admins` left false and admin merges counted as
  bypass; a forgery run that includes a pull request editing its own tables.
- The harvest rows (2-3), after which the founder sets ECC's
  `hooks_enabled` false.
- Then the Codex ride-along adapter (3-5; `apply_patch` must meet the deny
  rows and the Stop hold). `felix dispatch` v0 in February at the earliest.

## 4. Not before February

`felix dispatch` and leases; the discovery schedule; discovery budgets, the
dispute protocol and the stopping rule; the Docker sandbox and behaviour
receipts; DSSE or in-toto receipts (and never a key on the enforcing path);
retiring the router (a charter change); team concurrency; a Factory Droid
adapter; outreach and pricing.

## 5. Signals that change the plan

- The blind request on the second project yields nothing a person will admit:
  move `coverage.tsv` ahead of the judge and run discovery again.
- The Elenchus checker cannot meet all seven controls against the
  `a45a985` / #16 pair: the qualified-judge claim is untestable on real code,
  and the control set goes back to the founder as an amendment.
- Recall on the sealed corpus does not beat the control arm: discovery adds
  nothing over a plain session. Say so plainly and narrow to the obligations
  people name.
- The replay is not byte-identical on two clean machines: do not publish it.
- False blocks in the founder's own sessions rise after a change: stop and fix
  their source before the next feature.
- Factory ships standing obligations in next-generation Missions, or
  Anthropic ships standing, blocking project obligations: re-verify the
  market. It informs the plan; it does not set it.

Versions: Beacon `v1.3.47` (`90b19ae`), codex-cli `0.162.0-alpha.17.2`, Felix plugin `0.49.308`.

## Two runs, and why the first counts for nothing

**Run 1 tested nothing, and still reported pass and fail rows.** Two causes, each now a refusal
in `mac-run.sh`:

- The rig's `mock.py` plays its plan only when the request carries the plan's marker,
  `PROBEMARK`. With the old default `RIG_PROMPT=go`, every Codex session ended on its first reply
  with no tool call, so the before and after runs compared two empty sessions.
- `beacon endpoint install` refused without `beacon-otelcol`, and the script carried on, so the
  after runs had no Beacon in place.

**Run 2 is the measurement.** It used `RIG_PROMPT="PROBEMARK go"` and a collector built from the
pinned commit. Its baseline was governed: Felix's deny blocked the `--no-verify` commit, the Stop
hold fired, and the typed commit landed with the hold firing after it.

## What it means for build or buy

Beacon's offline Codex reader parses the same rollout file Felix would read, so parity was the
expected result, not a finding in Beacon's favour. The raw rollout already holds the
`write_stdin` chars (parity `typed_chars` is 1 of 1, equal 1). After the fact detection of typed
input is therefore not a reason to take Beacon on: it belongs in Felix's own Codex transcript
reader, which roadmap §3 item 5 already names ("one transcript reader per host"). The 10-02 audit
proposed the same check: at Stop, scan the rollout's `write_stdin` chars against the deny rows.

Beacon's real value would be a maintained parser across hosts, and that is untested here: Droid
was not run, and the live path was not measured. Its cost is an install that edits Codex's
config, turns on prompt logging, and adds hooks that run alongside Felix's (and shift Felix's hook
order).

**Verdict: no go on Beacon as the Codex reader.** Felix writes its own Codex transcript reader, and
Beacon stays at most an optional extra source behind it. Droid and Beacon's live OTLP path were
not run, so this verdict does not cover them (see "The founder's decision" at the end). Any change
to `docs/direction.md` is the founder's; none is needed for this, since roadmap item 5 already
holds the reader.

## Fixes the run asked for, now in `mac-run.sh` and `test.sh`

- `RIG_PROMPT` defaults to `PROBEMARK go`, and a prompt without `PROBEMARK` refuses
  (`mac_prompt_unmarked`). The header no longer says the mock plays whatever the prompt says.
- Baseline rows refuse the run (`mac_baseline_ungoverned`) unless the before runs were governed:
  the deny rollout holds `Command blocked by PreToolUse hook`, the stop and stdin rollouts a
  `hook_prompt`, and the stdin fixture the spike commit.
- A failed `beacon endpoint install` refuses the run (`mac_install_failed`). `BEACON_OTELCOL` is
  required, must be executable (`mac_otelcol_missing`), and the header gives the build.
- The behaviour comparison normalises the `hook_run_id` index, chunk ids, shell session ids (both
  `session ID <n>` and `"session_id":<n>`) and short commit hashes in `[main <hash>]`.
- The live OTLP row reads `not_run` unless a `beacon-otelcol` process ran during the after runs.
- The fill-ins are documented in the header as run: `RIG_DENY_PLAN` defaults to
  `plan-deny1.json`; `RIG_STOP_PLAN` is the one step `plan-stop.json`; `SEED_TRUST_CMD` reads
  `hookslist.py`'s output; `FELIX_MARKETPLACE` is a marketplace directory, not the checkout;
  `rig/fixture.sh` is called directly as `<home> <checkout>` after clearing what an earlier call
  for the same name left; `TMO` defaults to 240.
- `test.sh` reverses a file with awk instead of `tac`, which macOS lacks.

The live OTLP path is still unmeasured: measuring it means starting `beacon-otelcol` on the
scratch config for the after runs, which the script does not do. For the Codex verdict it is not
worth a run on its own.

**Refusals before the measured attempt, each one right.**
